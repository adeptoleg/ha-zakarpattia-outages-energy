# Zakarpattia Outages для Home Assistant

Графік погодинних відключень електроенергії для Мукачева та всього Закарпаття. Картка показує всі 12 підчерг на сьогодні й завтра та виділяє вашу. Кожна клітинка відповідає 30 хвилинам.

## Встановлення

Мінімальна версія Home Assistant Core — 2024.11.0.

1. У HACS відкрийте меню з трьома крапками, виберіть **Custom repositories** і додайте `https://github.com/adeptoleg/ha-zakarpattia-outages-energy` з типом **Integration**.
2. Знайдіть **Zakarpattia Outages** у HACS, завантажте інтеграцію та перезапустіть Home Assistant.
3. У **Налаштування → Пристрої та служби → Додати інтеграцію** знайдіть **Zakarpattia Outages**. Виберіть підчергу від `1.1` до `6.2`, яку Закарпаттяобленерго призначило вашій адресі.
4. За наявності датчика мережі виберіть його в тому ж діалозі. Змінити або додати датчик пізніше можна через **Переналаштувати** в меню інтеграції.

Для ручного встановлення скопіюйте папку `custom_components/zakarpattia_outages` до `custom_components` у каталозі конфігурації Home Assistant. Перезапустіть Home Assistant і виконайте кроки 3–4.

## Готова панель «Графік світла»

Після налаштування першої підчерги відкрийте **Графік світла** в бічному меню Home Assistant. Панель показує графік усіх підчерг, виділяє вашу і показує найближчі відомі часи відключення та відновлення. Якщо налаштовано кілька підчерг, перемикайте їх над таблицею. Фактичний стан мережі відображається після підключення датчика. Кнопка **Налаштування** відкриває сторінку інтеграції.

## Картка для іншої панелі

Після додавання інтеграції оновіть вкладку Home Assistant. У режимі редагування панелі додайте картку **Zakarpattia Outages** або вставте YAML у ручному редакторі карток.

```yaml
type: custom:zakarpattia-outages-card
```

За наявності кількох підчерг укажіть, із якої брати виділення. Замініть ідентифікатор прикладу на ідентифікатор вашого сенсора **Стан за графіком**.

```yaml
type: custom:zakarpattia-outages-card
entity: sensor.schedule_status_5_1
```

На вузькому екрані таблицю можна прокручувати вправо. Години в таблиці відповідають часу `Europe/Kyiv`. Штрихування позначає неопубліковані дані. У календарі Home Assistant час відображається відповідно до налаштувань платформи.

## Сутності

| Сутність | Що показує |
| --- | --- |
| Календар **Графік відключень** | Інтервали ГПВ для вибраної підчерги. |
| Сенсор **Стан за графіком** | `outage_scheduled` в інтервалі ГПВ, `no_outage_scheduled` поза інтервалом опублікованого графіка, `unpublished` коли графіка підчерги немає. |
| Сенсор **Наступне відключення за графіком** | Час наступного відомого початку, якщо його опубліковано. |
| Сенсор **Наступне відновлення за графіком** | Час завершення поточного або наступного відключення, якщо він відомий. Для автоматизацій доступний як сенсор часу. |
| Бінарний сенсор **Мережа** | Фактичне живлення за даними підключеного датчика. `on` означає, що мережа є, `off` що мережі немає, `unavailable` що показання недоступне. |

Для **Мережі** можна використати `binary_sensor` інвертора або реле контролю напруги, яке залишається на зв’язку за відсутності мережі. Увімкніть опцію інвертування, якщо ваш датчик дає `on` при зникненні напруги. Якщо інвертор передає напругу числовим сенсором, його можна перетворити на бінарний датчик у Home Assistant через шаблон із порогом, який відповідає показанням вашого пристрою. Для фіксації зникнення мережі Home Assistant і датчик мають залишатися живими.

Атрибут `schedule` сенсора стану містить інтервали вибраної підчерги у форматі ISO 8601. Значення `null` означає, що графіка на дату немає або джерело недоступне. Порожній список означає опублікований день без запланованих відключень. Атрибут `all_queues` містить по 48 півгодинних позицій на кожну опубліковану підчергу. `1` позначає заплановане відключення, `0` позначає решту часу опублікованого графіка.

## Тригери для автоматизацій

| Подія | Тригер Home Assistant |
| --- | --- |
| Фактично вимкнули мережу | Стан сенсора **Мережа** з `on` на `off`. |
| Фактично відновили мережу | Стан сенсора **Мережа** з `off` на `on`. |
| Наближається початок ГПВ | Початок події календаря зі зміщенням, наприклад `-00:30:00` для попередження за 30 хвилин. |
| Наближається заплановане відновлення | Тригер часу від сенсора **Наступне відновлення за графіком** зі зміщенням або кінець події календаря. |
| Оновили графік підчерги | Подія `zakarpattia_outages_schedule_changed` з полями `queue` та `dates`. Вона охоплює публікацію, зміну або зняття графіка після першого успішного зчитування. |

Приклад тригерів для однієї автоматизації. Підставте ідентифікатори своїх сутностей у редакторі Home Assistant та додайте потрібні дії.

```yaml
triggers:
  - trigger: state
    entity_id: binary_sensor.grid_power_5_1
    from: "on"
    to: "off"
    id: grid_lost
  - trigger: state
    entity_id: binary_sensor.grid_power_5_1
    from: "off"
    to: "on"
    id: grid_restored
  - trigger: calendar
    entity_id: calendar.outage_schedule_5_1
    event: start
    offset: "-00:30:00"
    id: scheduled_outage_soon
  - trigger: event
    event_type: zakarpattia_outages_schedule_changed
    event_data:
      queue: "5.1"
    id: schedule_changed
```

Тригери з указаними `from` та `to` пропускають переходи через `unavailable`, щоб втрата зв’язку з датчиком не створювала хибну подію відключення. Подія зміни графіка також містить дати у форматі `YYYY-MM-DD` у полі `trigger.event.data.dates`.

## Джерело

Інтеграція раз на 10 хвилин читає JSON спільноти [OE_OUTAGE_DATA](https://github.com/yaroslav2901/OE_OUTAGE_DATA). При помилці джерела картка позначає графік недоступним. Бінарний датчик мережі продовжує працювати незалежно. ГПВ можуть змінюватися впродовж дня. Для фактичного стану мережі є окремий датчик.

- [Графіки та перевірка підчерги на сайті Закарпаттяобленерго](https://zakarpat.energy/customers/break-in-electricity-supply/schedule/)
- [Офіційний канал Закарпаттяобленерго](https://t.me/s/zakarpatenergyofficial)

Перевірено на Home Assistant Core 2024.11.0 і 2026.11.0.
